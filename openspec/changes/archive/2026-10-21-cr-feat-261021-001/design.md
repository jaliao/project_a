## Context

既有「月報」（`lib/data/monthly-report.ts`）已示範本次要沿用的核心手法：
- Asia/Taipei 月份邊界（`taipeiYearMonth`／`addMonths`／`taipeiMonthBounds`，均為該檔內部 private helper，專案目前無共用時區 util，沿用「各資料層各自實作」慣例，不抽共用模組）。
- 「累計去重」：同一學員在同一冊可能有多筆 `InviteEnrollment`（跨班），只取**最早一筆 `status = 'approved'` 的 `joinedAt`** 當作該學員對這一冊的「加入時間」，避免跨班重複計入。
- 單位歸屬：`churchKeyOf(user)` —— `churchType === 'church' && churchId != null` 才歸屬該教會，其餘（`other`/`none`）歸入 `null`（「其他／未填」）。

本次與月報的差異：月報只需算「本月底」與「上月底」兩個時間點的累計數（`bookCumulative(cid, prevEnd, end)`），本次需要**一整年 13 個時間點**（年初前的基準 + 1～12 月底）才能畫出整年趨勢，且冊別不限第一/二冊（`BOOK1_CATALOG_ID`/`BOOK2_CATALOG_ID` 寫死），而是由使用者從 `CourseCatalog` 清單中任選。

## Goals / Non-Goals

**Goals:**
- 管理者可任選一冊＋一年度，看到該年度 1～12 月（或至目前月份）各教會的累計人數折線趨勢與每月新增/累計明細表。
- 統計口徑與既有月報一致（`approved`、去重累計、教會歸屬規則相同），管理者不需要學兩套邏輯。
- 圖表不因教會數量多而難以閱讀。

**Non-Goals:**
- 不做「跨年度」比較（例如同一月份不同年份疊圖）——本次僅單一年度視圖，日後有需要可另開 CR。
- 不新增任何每月快照表——沿用月報「全部即時由既有時間戳推導」的作法，不持久化統計結果。
- 不處理「結業人數」成長（只算報名／`joinedAt`）——使用者已確認本次僅需報名人數口徑。
- 不在此頁提供教會或冊別本身的新增/編輯（那是既有 `/admin/churches`、`/admin/course-catalog` 的職責）。

## Decisions

- **折線圖僅畫累計人數最高的前 8 個教會 + 「其他／未填」彙總，其餘教會只出現在表格。**
  理由：教會清單可能有數十間，全部畫線會讓圖表無法閱讀（比照 `church-distribution-charts.tsx` 已用「Top 5 / Low 5」處理類似的擁擠問題）；表格不受此限制，仍完整列出所有教會，不遺漏資料，僅圖表做視覺篩選。

- **年度與冊別皆由查詢參數（`?year=YYYY&catalogId=N`）表示，沿用月報 `?month=YYYY-MM` 的既有慣例（`router.push` + `<select>`）。**
  理由：維持同一頁面「換篩選條件＝換網址」的既有後台慣例（`MonthSelect` 模式），好分享連結、重新整理不丟篩選狀態，且不需要額外狀態管理函式庫。

- **冊別清單用 `getAllCourses()`（`lib/data/course-catalog.ts`），不限 `isActive = true`。**
  理由：已下架或尚未開放報名的冊若曾經開過課、有歷史報名資料，仍應能回顧其成長趨勢；是否開放報名是另一回事（`isActive` 控制的是能否建立新班級，不代表歷史資料該被隱藏）。

- **年度清單的最早年份取「全部冊別」最早一筆 `InviteEnrollment.joinedAt` 所在年度（不依選定冊別重算），與月報 `getAvailableReportMonths()` 的作法一致（月份清單也不依冊別變化）。**
  理由：維持兩處「可選期間」清單的計算邏輯一致，且避免換冊別時年度選單跳動造成困惑；選到「這一冊在這一年沒有任何資料」時頁面顯示空狀態即可，不需要限制選單本身。

- **累計基準（年初前）需要額外查一次「< 當年 1/1」的累計人數，而非從 0 起算。**
  理由：「成長」趨勢圖若從 0 起算，會讓早年就累積大量學員的冊看起來「今年才暴增」，誤導判讀；用去年底累計當基準線，1 月的「月增人數」才是真正當月新增的人數，語意與月報的 `momDelta` 一致。

## Risks / Trade-offs

- [選定年度與冊別組合下完全沒有資料（例如某冊剛開放、尚無任何報名）] → 頁面比照月報 `hasData`/空狀態寫法，顯示「該冊在此年度尚無報名資料」，不報錯、不顯示空圖表。
- [前 8 名門檻可能讓管理者誤以為圖表＝全部資料] → 圖表標題／說明文字明確標註「僅顯示累計人數前 8 名教會，完整名單見下方表格」。
- [選定年度為未來年度（可選清單理論上不會出現，但防呆）] → 年度參數驗證不合法或超出可選範圍時，比照月報 `normalizeMonth` 的作法，退回最新可選年度。

## Migration Plan

純新增功能，無資料庫變更、無既有資料相容性問題：
1. 新增 `lib/data/church-course-growth.ts`、三個頁面/元件檔案。
2. `app/[locale]/(admin)/admin/page.tsx` 新增一張功能卡（純新增一個物件，不影響既有卡片）。
3. 回退：移除新增檔案與該功能卡即可，不影響任何既有功能或資料。
