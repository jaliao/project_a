# Proposal: cr-spec-260720-001 教材申請內容可修改（版本／數量），學員申請改為參考依據

## Why

目前教材申請的繁/簡數量完全由「已核准學員的選版（`materialChoice`）」推導，申請時自動帶入且不可調整，server 端並以剩餘量為硬上限。實務上學員的選版只是參考：老師與管理者需要在送出申請前調整書籍版本與數量（例如幫學員改版本、排除某本、加購額外本數），現行流程無法支援。

## What Changes

- **申請教材對話框改為「逐本清單編輯」**：申請時顯示由學員申請帶入的書本清單（學員、書名、版本）作為預設值，老師/管理者可於送出前：
  - 逐本修改版本（繁 ↔ 簡）
  - 取消勾選（本次不申請該本）
  - 新增「額外加購」書本（不綁定學員，僅指定版本與數量）
- **學員申請降為參考依據**：移除「不可超額」的硬上限驗證；學員選版統計仍於 UI 顯示（總需求／已申請／尚未申請）供對照，但不再限制申請數量上下限。
- **「申請教材」按鈕條件放寬**：不再因「尚未申請＝0」而停用；開課前（未開始／未取消／未結業）皆可再申請（含純加購）。
- **管理者可於前台課程頁修改／申請教材**：比照班級管理前台化方向，管理者進入課程詳情頁可見與講師相同的「教材申請作業」區塊並可執行申請；相關 server actions 授權由「僅講師」擴為「講師或管理者」。
- **「完成教材申請」機制（解鎖開課）**：老師/管理者可將課程標記為「教材申請已完成」——學員都不需申請教材、或老師/管理者判定不需（再）申請教材時，即可完成教材申請以通過開課門檻。開課條件中「尚未申請需求＝0」改為「尚未申請需求＝0 **或** 教材申請已完成」；既有「所有教材訂單皆已收件」條件維持不變。完成後可於開課前取消（重新開放申請）。

## Capabilities

### New Capabilities

（無）

### Modified Capabilities

- `material-book-items`：書本項目不再嚴格一對一綁定學員選版——申請時可逐本改版本、排除項目，並支援「額外加購」項目（無對應學員）；快照規則涵蓋調整後的版本與加購項目。
- `course-multi-material-order`：①單一地址申請不再「自動帶剩餘、不可編輯」，改為逐本清單可編輯；②移除「不可超額」上限驗證與「尚未申請＝0 停用申請按鈕」限制，學員統計改為參考顯示；③教材申請作業之操作者由講師擴及管理者；④教材申請作業區塊新增「完成教材申請」／「重新開放申請」操作與完成狀態顯示。
- `course-status`：開課門檻之「尚未申請教材需求為 0」條件放寬為「尚未申請需求為 0 **或** 教材申請已完成」；其餘條件（已核准學員 ≥1、所有訂單已收件）不變。

## Impact

- **Server Actions**：`app/actions/course-order.ts`（`applyMaterialOrder`：授權擴及管理者、接受編輯後的書本清單、移除剩餘量上限驗證；新增完成／重新開放教材申請 actions）、`app/actions/course-invite.ts`（`startCourseSession` 開課門檻放寬）
- **開課門檻**：`lib/utils/course-start-gate.ts`（`evaluateCourseStartGate` 增加「教材申請已完成」豁免）
- **資料層／工具**：`lib/data/material-items.ts`（書本項目推導＋加購項目）、`lib/utils/material-progress.ts`（進度改為參考性統計）
- **Schema**：`lib/schemas/course-order.ts`（申請 payload 增加逐本清單）；`prisma/schema/course-order.prisma`（`MaterialShipmentItem` 學員欄位需容許加購項目、可能新增加購標記）；`CourseInvite` 新增教材申請完成時間欄位
- **UI**：`components/course-session/material-order-dialog.tsx`（逐本清單編輯）、課程詳情頁教材申請作業區塊（管理者可見可操作）
- **文件**：`doc/管理者操作手冊.md`、`doc/老師手冊.md` 需同步更新；`config/version.json` patch +1（於 apply 階段執行）
