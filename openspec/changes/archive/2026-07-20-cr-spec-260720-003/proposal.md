# Proposal: cr-spec-260720-003 教材申請作業 UI 優化（三單元化）

## Why

cr-spec-260720-001 後的教材申請作業區塊資訊量變大（參考統計、訂單清單、申請／完成標記按鈕與多種提示混在同一塊），層次不清：統計與進度混排、按鈕缺乏用途說明，老師/管理者不易一眼掌握「需求多少、申請到哪、下一步做什麼」。

## What Changes

- **教材申請作業區塊重構為三個單元**（同一卡片內分段，順序固定）：
  1. **學員教材需求統計**：總需求（依已核准學員選版統計，標示僅供參考）。
  2. **教材申請進度**：已申請／尚未申請統計＋逐筆訂單清單（含各訂單狀態與動作）；「教材申請已完成」狀態列亦在此呈現。
  3. **申請作業**：申請注意事項與**功能按鈕說明**（逐顆按鈕說明用途），功能按鈕並列：「**申請教材**」｜「**已完成申請**」。
- **完成標記按鈕更名**：「無須額外申請」→「**已完成申請**」（語意＝本課程教材申請作業已完成、不需再購買）；確認視窗標題同步更名。取代上一輪未 commit 的「無須額外申請＋引導文字」排版（引導文字改由功能按鈕說明承載）。
- 按鈕行為不變：「申請教材」開課前且未標記完成時可按；「已完成申請」標記後停用申請、豁免開課教材需求條件，可「重新開放申請」。

## Capabilities

### New Capabilities

（無）

### Modified Capabilities

- `course-multi-material-order`：「講師端多訂單清單呈現」requirement 之教材申請作業區塊結構改為三單元（需求統計／申請進度／申請作業），並定義申請作業單元須含注意事項與功能按鈕說明；完成標記按鈕定名「已完成申請」。

## Impact

- **UI**：`app/[locale]/(user)/course/[id]/course-detail-actions.tsx`（教材申請作業區塊重排；純呈現，無 action／資料層變更）
- **i18n**：`messages/zh-TW.json`／`en.json` `course.material.*`（單元標題、注意事項、按鈕說明、按鈕更名；zh-CN 重新產生）
- **文件**：`doc/老師手冊.md`、`doc/管理者操作手冊.md` 按鈕名稱與區塊描述同步；`config/version.json` patch +1
- **無 migration**；`finalizeMaterialOrders`／`reopenMaterialOrders` 等 actions 不變
- 含納上一輪未 commit 之按鈕命名調整（一併於本 change 定案為「已完成申請」）
