## Why

「世代倍增」月報（`lib/data/monthly-report.ts` `generations()` / `generationTeacherDetails()`）的「教師集合」目前只要求「使至少一人於 cutoff 前結業」，不要求教師本人自己也已結業。這導致實測異常：盧正義（PA260268）自己的啟動靈人結業紀錄（2026-10-04，張幸瑜班）晚於他自己開班教出的學生結業時間（9 月前），在 `/api/admin/dashboard/generations/export?month=2026-09` 這類月報快照下被誤判成第 0 代（根節點）——但他其實是有老師的，鏈路本身正確，只是當月他自己還查不到結業紀錄。

經與使用者討論確認：月報「依月份 cutoff 計算」的設計本身保留不變（`CR-FIX-261024-001` 已討論過「改用全量資料」方案，確認不採用，維持「世代隨月份連動」現狀，本 CR 不重複該討論）。改走另一條路徑：收緊「教師集合」的資格認定。

## What Changes

- `generations()` / `generationTeacherDetails()` 的教師集合篩選條件新增一項：除了「使至少一人於 cutoff 前結業」，還要「本人在 cutoff 前也有自己對應書籍的結業紀錄」才列入教師集合／世代計算。不符合者（如 9 月當下的盧正義）**整列不出現**在該月報表與下載的 raw data 中，而非被誤顯示成第 0 代。
- 新增固定例外：黃國倫（`spiritId = 'PA260001'`，系統創始人）正式環境裡本人完全沒有啟動靈人結業紀錄（唯一合理的真根節點），永遠視為合格並落在第 0 代，不受上述新規則限制。
- 「世代倍增數據定義說明」對話框文字同步更新，加入「教師本人須已結業對應書籍」與「黃國倫為固定例外」兩點說明。

## Capabilities

### Modified Capabilities
- `admin-dashboard-monthly-report`：「世代倍增子區塊」「世代倍增原始資料下載」「世代倍增數據定義說明」三個 Requirement 新增教師資格認定規則與黃國倫固定例外。

## Impact

- **後端**：`lib/data/monthly-report.ts` 的 `generations()`、`generationTeacherDetails()` 兩個函式。
- **前端**：「世代倍增」子區塊的「說明」對話框文字（靜態文案，無需查詢資料庫）。
- 已用正式環境真實資料驗證新規則本身乾淨：2026-09 cutoff 下僅盧正義被排除，排除後沒有連帶讓任何人變成新的假根節點，過濾後第 0 代僅剩黃國倫一人。
- 不涉及 `CR-FIX-261024-001` 已處理的「禁止未結業者取得老師身分／開班」防呆（已完成並關閉的另一張 CR）。
- 不更動月報的月份 cutoff 設計本身（`admin-dashboard-monthly-report` 的「月報區塊與月份切換」「世代隨月份連動」既有行為維持不變）。
