## 一、管理者角色與權限

系統採**多重身分（roles）**設計，一個帳號可同時擁有多個身分：

| 身分 | 說明 |
|------|------|
| `user` | 基線身分，所有人都有 |
| `teacher_1` | 啟動靈人講師（可開設「啟動靈人」課程） |
| `teacher_2` | 啟動豐盛講師（可開設「啟動豐盛」課程） |
| `teacher_3` | 啟動得勝講師（可開設「啟動得勝」課程） |
| `admin` | 可進入後台、管理會員與課程 |
| `superadmin` | 最高權限，額外可授權 `superadmin` 身分（admin 不可） |

> 講師資格**依書籍區分**，並非單一講師身分。一位會員可同時持有多個書籍講師身分。「身分 ↔ 書籍」對應集中於 `lib/auth-roles.ts`（`TEACHER_ROLE_BY_CATALOG`）。

權限判定集中於 `lib/auth-roles.ts`：

- `canAccessAdmin(roles)` — 是否可進後台（admin / superadmin）
- `canTeachAny(roles)` — **開課入口**判定：是否具任一書籍講師身分（或 admin / superadmin）。決定是否顯示「新增授課」入口。
- `canTeachBook(roles, courseCatalogId)` — **逐書授課資格**判定：是否具該書對應的講師身分（admin / superadmin 豁免，可開所有書）。開課精靈 Step 1 與 Server Action 皆以此把關。
- `isSuperadmin(roles)` — 是否為最高管理員

> ⚠️ 為避免自鎖，系統**禁止移除自己帳號的 admin / superadmin 身分**。

## 二、進入後台

1. 以管理者帳號登入。
2. 點選右上角 **後台管理**（僅 admin / superadmin 可見），進入 `/admin`。
3. 後台首頁為**功能按鈕網格**，包含：儀錶板、開課管理、會員管理、教材管理、課程目錄、系統設定等入口。

## 三、後台儀錶板

路徑：`/admin/dashboard`

統計以**三個區塊**呈現：

**學員分析**（包含講師）：

| 卡片 | 說明 |
|------|------|
| 學員總數 | 系統中所有會員（User）總數 |
| 近期活躍學員數（7 天內登入） | 最近 7 天內有登入的會員數 |
| 會員性別 | 圓餅圖：男／女／未設定分布 |
| 各年齡會員人數 | 柱狀圖：依出生年推算，七組距（20 歲以下～71 歲以上）；未填出生年人數註記於卡片下方 |
| 各教會的會員總數 | Top 5／Low 5 兩張圓餅圖：人數最多前五間與其餘中最少五間（教會 ≤ 5 間時只顯示 Top 5）；「其他（自填）」「未填」人數註記於 Top 5 卡片下方 |

**講師分析**：

| 卡片 | 說明 |
|------|------|
| 啟動講師 | 持有 `teacher_1` 身分的不重複人數 |
| 豐盛講師 | 持有 `teacher_2` 身分的不重複人數 |
| 得勝講師 | 持有 `teacher_3` 身分的不重複人數 |

**課程分析**：

| 卡片 | 說明 |
|------|------|
| 招募中課程總數 | 招募學員中的課程（尚未開始上課、未取消、未結業） |
| 進行中課程總數 | 已開始上課、未取消、未結業的課程 |
| 已結業課程總數 | 已完成結業（且未取消）的課程 |
| 已放棄課程總數 | 已取消的課程 |

> ⚠️ 講師人數**直接以書籍講師身分（teacher_1～teacher_3）計數**，不再連動結業證書。指派書籍講師身分即計入對應人數。

## 四、會員管理

路徑：`/admin/members`

### 清單功能
- ⚠️ **未輸入任何條件時不顯示清單**：為避免一次載入全部會員拖慢頁面，需先**輸入搜尋**或**選擇任一篩選**，清單才會出現。
- **搜尋**：搜尋姓名、暱稱、Email、**啟動編號**（輸入框 debounce 300ms）。
- **篩選下拉**（可與搜尋並用，採 AND）：
  - **性別**：全部／男／女／未指定
  - **身分**：全部／一般會員／啟動靈人講師／啟動豐盛講師／啟動得勝講師／管理者／超級管理者（「包含」語意，例如選「啟動靈人講師」會列出所有持有 `teacher_1` 者）
  - **所屬教會**：全部／各教會／其他／無
- **分頁**：每頁 **30 筆**，下方有「上一頁／下一頁」，並顯示「第 X / Y 頁」與符合條件**總筆數**；變更搜尋或篩選會回到第 1 頁。
- **排序**：依加入日期、其次姓名。
- 列表顯示會員**身分 Badge**（多重身分一併呈現）。
- **機敏資料遮蔽**：Email 欄預設以 `***` 遮蔽，**點一下**該欄位即可檢視明文、再點一下恢復遮蔽（逐筆獨立切換，不影響搜尋）。
- **匯出**：「匯出 N 筆」會依**目前所有篩選條件**匯出（N = 符合條件總數，非僅當頁 30 筆）；「匯出全部」則忽略條件匯出所有會員。

### 新增會員
1. 點選 **新增會員**。
2. 系統會自動：核發**啟動編號** + 產生**臨時密碼** + 加入 Email 白名單。
3. ⚠️ **臨時密碼僅顯示一次**，請立即複製交付給該會員。

> ℹ️ **seed 名冊帳號不寄系統信**：名冊匯入的會員帳號 Email 為合成信箱（`xxx@seed.iwillshare.org.tw`，實際不存在），系統對這類地址**一律略過寄信**（臨時密碼、結業信等），以免退信。請以畫面顯示的臨時密碼直接交付會員；該會員之後於個人資料設定並**驗證真實通訊 Email** 後，系統信件即恢復正常寄送。

### 會員詳情
路徑：`/admin/members/[id]`，以四個分頁（Tabs）呈現：**基本資料／學習階層／講師身分／特殊設定**。

- **基本資料**：姓名、英文名稱、性別、**年齡**、顯示名稱方式、所屬教會、**電話**、**授課老師編號（teacherNo）**、身分（唯讀 Badge）、學習紀錄、授課紀錄。
  - ⚠️ 後台所有呈現會員名字之處皆採會員的**顯示名稱**（系統標準/資安），不直接顯示真實姓名。
  - **年齡**：依會員填寫的出生年（西元）以「當年 − 出生年」估算顯示（如 `36 歲`）；未填出生年顯示「—」。
  - **機敏資料遮蔽**：Email 與電話預設以 `***` 遮蔽，**點一下**檢視明文、再點一下恢復遮蔽（電話未填顯示「—」）。
  - **學習紀錄／授課紀錄**：以**標準課程卡片**（與課程頁一致：課程編號、標籤、狀態、報名人數、開課日）呈現，手機單欄、桌機兩欄；**含招生中課程**（學習紀錄為已核准報名、授課紀錄為建立的所有課程），**招生中排最前**、其後依開課時間新→舊；**點卡片**可直接進入該課程頁。無紀錄顯示「尚無學習紀錄／尚無授課紀錄」。
  - **活躍度**：另以獨立區塊呈現會員活躍度——
    - **最後登入時間／上次登入時間**：每次登入成功會記錄，並把舊的最後登入平移為上次登入；無紀錄顯示「—」。
    - **首次登入**：曾登入過顯示「已完成」，否則「尚未登入」。
    - **首次補填基本資料**：真實姓名與手機皆已填寫顯示「已補填」，否則「尚未補填」。
    - **臨時密碼**：以臨時密碼建立之帳號已改密顯示「已更改」、未改顯示「尚未更改」；純 Google（無密碼）帳號顯示「不適用」。
- **學習階層（師生傳承樹）**：以縮排樹狀呈現上一層老師與下方 N 層學生（僅限「啟動靈人」、以已結業 `graduatedAt` 為準）。展開層數由系統設定 `hierarchy_depth` 控制。
- **講師身分**：
  - **推薦歷程**：唯讀顯示他人（各課程老師）推薦此會員成為講師的回饋（推薦書別、備註、推薦老師、時間）。
  - **設定講師身分授權**：三本書講師身分以**卡片**呈現，點「授予/移除」→ **確認對話框** → 執行。**授予**講師身分會自動**寄通知信**給該會員；移除不寄信。
- **特殊設定**：
  - **暫停會員 / 恢復會員**：暫停會**封鎖登入**並記錄暫停時間、操作人員、原因（下拉：密碼外洩／使用者要求／其他原因，可自填補充；「其他原因」補充必填）；暫停中顯示資訊與「恢復會員」。不可暫停自己。
  - **補發密碼**：重設臨時密碼並重新顯示一次（同舊「重設密碼」）。
  - **帳號修改**：變更會員**登入 Email**——輸入新 Email、確認視窗（新舊並列）後**立即生效**。新 Email 自動加入白名單、舊 Email 白名單停用；**不影響**通訊 Email、Google 綁定與課程資料，不寄通知信（請當面告知會員下次用新帳號登入）。**Google 登入（無密碼）會員也可在此代改**（會員前台無法自改）。
  - **特殊身分授權**：授予/移除 `admin`、`superadmin`。⚠️ **admin 不可授權 superadmin**（UI 不顯示該選項、後端亦拒絕）；**superadmin 可授權各種身分**；任何人不可移除自己的管理身分。
  - **危險操作**：刪除會員（受 `ENABLE_MEMBER_DELETE` 控制）。

> 暫停效果：被暫停會員無法登入；既有 session 於下次請求即時被擋並導向獨立的「帳號已暫停」頁（`/account-suspended`，含「重新登入」連結）；恢復後從該頁「重新登入」即可正常登入。

### 未啟用會員清單
路徑：後台首頁 **未啟用會員** 卡片（`/admin/members/inactive`），僅管理者可存取。

- 列出**從未登入過**（`lastLoginAt` 為空）的會員，欄位：啟動編號、姓名、Email（預設 `***` 遮蔽、點一下檢視）、身分、建立時間、臨時密碼狀態，並可點「查看詳情」。
- 用途：追蹤灌檔／代建立但尚未設定自己帳號的會員。

> **找回帳號（自助）**：未登入過的會員可於首頁／登入頁的 **找回我的帳號**（`/recover-account`）以中文名字 → 課程選擇題驗證 → 確認/修改 Email → 收臨時密碼登入。當會員回報「請洽管理員」（查無資料／多筆同名／無可出題的課程資料），請由後台協助：確認該會員 Email 後用 **會員詳情 → 補發密碼** 重發臨時密碼，或先用 **新增會員／修正 Email** 後再交付臨時密碼。

## 五、多重身分管理

於**會員詳情頁**編輯身分：**書籍講師身分**在「講師身分」分頁（卡片授權），**admin/superadmin**在「特殊設定」分頁（`updateMemberRoles`）：

- 書籍講師身分（`teacher_1`～`teacher_3`）：「講師身分」分頁卡片授予/移除（授予會發信）。
- **特殊身分**（`admin`、`superadmin`）：**權限分級** —— `admin` 可授予/移除書籍講師與 `admin`，但 **不可授予/移除 `superadmin`**；`superadmin` 可授予/移除所有身分。
- 賦予任一書籍講師身分會讓該會員**看到「新增授課」入口**（第一層）；實際能開哪門課由開課精靈 Step 1 依書籍講師身分逐書把關（第二層，admin/superadmin 豁免）。
- ⚠️ 不可移除**自己帳號**的 admin / superadmin 身分。
- 身分變更**即時生效**：JWT callback 於每次請求自 DB 同步角色，無需該會員重新登入。

## 六、Email 白名單與存取控制

- 只有列在白名單（`WhitelistedEmail`，`isActive = true`）的 Email 才能透過 Google OAuth 登入。
- 透過後台「新增會員」建立帳號時會**自動加入白名單**。
- 未授權的 Email 登入會被導向 `/login?error=NotWhitelisted`。

> 若有人反映 Google 登入顯示「未授權」，代表其 Email 不在白名單，請以「新增會員」建立或聯絡技術人員加入名單。

## 七、開課管理

路徑：`/admin/course-sessions`（全站所有開課，admin+）

- **文字搜尋**：課程名稱 / 講師 / 學員。
- **下拉篩選**：課程名稱、進度狀態、日期區間。
- 顯示**總筆數**，預設列出前 30 筆。
- 課程卡片標題上方顯示**課程編號**（`#123`，全站課程卡片一律顯示，可用於操作紀錄追溯與客服溝通）。
- 點擊課程**另開新視窗**進入課程詳情頁——**學員新增/移除、狀態操作（重新招募/結業/取消）、操作 LOG 皆於課程詳情頁進行**（見第十七、十八章）。
- **編輯課程人數（覆寫上限）**：管理者於招生中課程的詳情頁可見「編輯」入口（icon＋「編輯」按鈕，不限課程建立者），並可將**預計人數設為超過**全域「班級人數上限」（老師仍受上限限制）；惟仍**不得低於已核准學員數**。
- **編輯進行中／已結業課程**：管理者（與授課老師）於**進行中**課程可修改課程名稱與**開始上課日期**；於**已結業**課程可再修改**結業日期**（不可早於開始上課日期、不可晚於今天；不會改動學員個人結業日）。已取消課程不可編輯。
- 已結業課程的課程詳情頁會顯示 **結業資訊** 區塊（最後課程日期、已結業 / 未結業名單與原因、**老師填寫的整體評分（五星）與見證**——有填才顯示）；此區塊**僅管理者與講師可見**，一般學員不會看到。

### 課程狀態操作（於課程詳情頁）
管理者可於**課程詳情頁**代講師執行狀態作業（不受開課者本人限制、不發通知）：

- **重新招募作業**：進行中課程可「退回招生中」（清除開始上課狀態），供修正誤按開始上課或重新收學員；既有報名與教材紀錄不受影響。
- **結業作業**：進行中課程可辦理結業（逐學員勾選，與講師相同流程）。
- **取消上課作業**：未取消、未結業課程可取消（填取消原因）。
- **教材申請作業**：管理者於課程詳情頁可見與講師相同的「教材申請作業」區塊，可代為**申請教材**（逐本清單：改版本／取消勾選／加購）、**取消申請**（限回填匯款前）、**回填匯款後五碼**、**確認收件**、以及「**已完成申請**」（標記教材申請完成）／「**重新開放申請**」（完成／重新開放會記入課程操作 LOG）。購買人資料仍以**課程講師**為準，訂單會記錄實際操作者。
- ⚠️ **開始上課**仍為講師專屬；後台已不提供任意狀態強制切換（含「已取消→招生中」回退）。

## 八、教材申請管理

路徑：`/admin/materials`

### 流程角色
教材流程：**老師/管理者申請 → 管理者批價 → 老師繳費並回填後五碼 → 管理者確認收款 → 寄送 → 老師確認收件**。
申請時書本清單依**學員申請帶入**（僅供參考、不設上限），可逐本**改版本**、**取消勾選**、**加購**（不綁學員，書名未填記為「額外加購」，出貨單照清單列印）。

### 後台操作
- 列表欄位：**編號 / 課程名稱 / 課程編號（`#courseInviteId`，獨立訂單顯示「—」）/ 講師 / 購買人 / 申請時間 / 狀態 / 操作 / 出貨單**。狀態 Badge 同前（待批價 / 待付款 / 待確認收款 / 待寄送 / 已寄送 / 已收件）。**一門課可有多筆教材訂單**，列表以「每筆訂單」為一列各自處理。
  - ℹ️ 列表已**移除「教材版本」「數量」欄**（資訊改於展開詳情查看），並**新增「課程編號」欄**便於對照課程。
- 展開**詳情**可查看：**每個收件地址的收件人姓名與連絡電話**、取貨方式、門市/地址、**該筆訂單的書本數量（繁/簡）**、批價金額、匯款帳號資訊（多行呈現）、老師回填的匯款後五碼。出貨單列印頁亦顯示該筆訂單的繁/簡本數。
- **收件地址內部備註**：詳情中可對**每個收件地址**填寫內部備註（工作人員紀錄用）——單一地址存於訂單、多地址各地址各一則；輸入後按「儲存備註」。此備註**僅後台可見、不顯示於老師/購買人前台**，並會列印於出貨單。
- **批價**：對「待批價」申請點 **批價**，填寫**金額**與**匯款帳號資訊**（多行文字欄，預設帶入系統設定值），送出後通知老師（通知內含完整匯款帳號資訊）。
- **確認收款**：老師回填後五碼後，狀態為「待確認收款」，核對銀行入帳後點 **確認收款**。
- **確認寄送**：**確認收款後**才可點 **確認已寄送** 標記出貨。
- ℹ️ 後台**不提供訂單編輯**（詳情不再有「編輯」按鈕）；申請內容以申請時快照為準，避免資料不一致。老師若需更正，可於**回填匯款前**自行「取消申請」後重新申請。
- ℹ️ 老師端開課門檻為「≥1 已核准學員、**教材需求已處理**（全數申請或按「已完成申請」）、**且該課程所有教材訂單皆已收件**」，故同一課程若有多筆訂單，需**每筆都完成收件**老師才能開課；標記「已完成申請」只豁免「尚有教材未申請」，**不**豁免既有訂單收件；且**有未收件訂單時無法標記**（按鈕灰色、server 亦拒絕），須全數收件後才可按。

### 匯款帳號資訊設定
- 於 `/admin/settings`「基本設定」可維護**教材匯款帳號資訊**（admin / superadmin 皆可），為**多行文字**（銀行分行、戶名、銀行代碼、帳號等），批價表單預設帶入；測試環境預設為「第一銀行淡水分行／戶名：希望之聲文化有限公司／銀行代碼：007／帳號：218-10-002087」（四行）。批價時會將當下帳號資訊**快照**至該筆訂單。

### 多地址寄送
- 教材可採**單一地址**或**多地址**寄送（`ShipMode`）。
- 多地址時採**逐本指派**：老師先建地址、再把每位學員的書指派到地址（可調版本、可加購；**未指派＝本次不申請**，可留待日後）；後台詳情與**出貨單列印**會於各地址顯示**書本清單（學員名＋教材所屬姓名＋繁/簡）**，繁/簡本數由指派結果推導。每個地址各自含**收件人**與**連絡電話**。加購項目無學員名，以書名（預設「額外加購」）呈現。
- **單一地址**訂單亦**記錄其自身涵蓋的書本**（送出時勾選的書本＋加購），詳情與列印顯示該訂單的**書本清單（學員名＋教材所屬姓名＋版本）**。因此同課程**先後多筆寄送**（多地址／單一地址）時，各筆書本歸屬明確、不會互相混入，方便製作印上名字的書。
- 後台需**逐批次確認寄送**；當所有批次都寄完，系統自動設定整筆訂單為已寄送（`shippedAt`）。

### 出貨單列印
- 路徑：`/admin/materials/[id]/print`。
- 點列表的 **列印** 按鈕產生出貨單（收件人、連絡電話、寄件方式、地址、書本數量、**該地址備註**）。
- 多地址時**每批次列印一份**。

## 十一、系統基本設定

路徑：`/admin/settings?tab=basic`（系統設定 → 基本設定）

- **學習階層深度（`hierarchy_depth`）**：admin / superadmin 皆可調整。
  - 控制會員詳情頁「師生傳承樹」往下展開的層數。
  - 有效範圍 **1–10**，預設 `3`。
- **班級人數上限（`class_max_capacity`）**：admin / superadmin 皆可調整。開課與編輯課程時老師可設定的每班人數上限，有效範圍 **1–99**，預設 `7`。調整後開課精靈與編輯課程的人數上限（欄位/提示/驗證）即時改依此值；**管理者編輯個別班級時可超過此上限**（見七、開課管理）。
- **教材匯款帳號資訊（`remittance_account`）**：admin / superadmin 皆可調整。多行文字（銀行分行、戶名、銀行代碼、帳號），批價表單預設帶入；測試環境預設為第一銀行淡水分行之帳號資訊。
- **結業信範本（`graduation_email_subject` / `graduation_email_body`）**：admin / superadmin 皆可調整。維護主旨與內文；老師確認結業時自動寄給結業學員。可用變數：`{{studentName}}`、`{{courseName}}`、`{{graduationDate}}`、`{{spiritId}}`；未設定時使用系統預設範本。
- 設定以 `AdminSetting`（key/value）儲存。

## 十三、常見管理情境

### 情境 A：新成員加入機構
1. 後台 **會員管理 → 新增會員**。
2. 複製系統顯示的**臨時密碼**交付對方（僅顯示一次）。
3. 對方首次登入走 Onboarding（設定密碼 → 填資料 → 取得啟動編號）。

### 情境 B：指派某人成為講師
1. 進入該會員的**詳情頁**。
2. 在多重身分編輯區，依其授課書籍勾選對應的書籍講師身分（如「啟動靈人講師」= `teacher_1`；可複選多本書）並儲存。
3. 變更即時生效，對方即可看到「新增授課」入口，並可開設所勾選書籍的課程。

### 情境 C：會員忘記密碼
- 若可自助：請對方使用登入頁 **忘記密碼？**。
- 若需協助：後台 **重設密碼**，將新臨時密碼交付對方。

### 情境 D：教材寄送作業
1. 學員於課程頁申請教材。
2. 後台 **教材管理** 查看申請 → 列印出貨單 → 寄出 → **確認已寄送**（多地址逐批次確認）。
3. 學員收到後在課程頁點「我已收到教材」，講師方可開始上課。

### 情境 E：協助講師處理課程
- 透過 **開課管理** 搜尋課程 → 另開課程詳情頁 → 可協助核准學員、結業、取消等（admin 具完整權限）。

## 十四、實體證書製作管理

進入路徑：後台功能格 **證書製作**（`/admin/certificates`）。用於追蹤實體結業證書的製作狀態。

### 清單來源與單位
- 一張證書＝**每人每階層一張**（同一人在同一課程階層跨多班只算一張，結業日取最新）。
- 清單來源為**已結業**的學員（結業流程完成、有結業日者）。

### 卡片內容（身分確認）
清單以**卡片**呈現（手機單欄、電腦多欄），每張卡片包含：
- **真實姓名**（中文＋英文並列，卡片主標題）：**證書上姓名以此為準**。中英文皆未填時顯示紅色「**未填真實姓名**」警示，請先請學員（或於會員管理）補齊真實姓名再製作。
- **性別 icon**（姓名旁）：藍色♂＝男、粉色♀＝女、淡色中性 icon＝未指定，協助確認同名者身分。
- 主標題下方依序列出欄位：**啟動編號**、**顯示名稱**（學員自選的暱稱顯示，**勿直接印上證書**）、**單位**（所屬教會／自填單位）、**課程階層－結業日**。
- 製作**狀態**；已完成者另顯示**製作日期／製作管理者**。

### 後台操作
- **篩選**：預設顯示**未完成**（尚未製作）；可切換**已完成**查詢已製作紀錄。
- **人名搜尋**：以真實姓名（中／英）、顯示名稱或啟動編號搜尋，與狀態篩選一併作用。
- **分頁**：每頁最多 **30 筆**。
- **標記已完成製作**：點「已完成製作」，系統記錄**製作日期**與**製作管理者**（操作者）。
- **還原**：對已完成者點「還原」可切回未完成（清除製作日期與管理者，**備註保留**）。
- **備註**：每張證書可填寫內部備註（工作人員紀錄用），輸入後按「儲存」。

## 十五、推薦講師管理

進入路徑：後台功能格 **推薦講師**（`/admin/recommendations`）。集中檢視課程老師對已結業學員的講師推薦，並追蹤處理狀態。

### 清單與狀態
- 來源：老師於課程結業後填寫的「講師資格回饋」中**推薦**者。
- 依**回饋時間由新到舊**排序；上方可切換 **未處理 / 暫不接受 / 已成為講師 / 全部**（預設未處理）。
- 每筆狀態：
  - **已成為講師**：該會員**已被指派對應書籍講師身分**（於「多重身分」指派後自動判定），無需處理。
  - **暫不接受**：管理者已記錄暫不接受（含備註、時間、管理者）。
  - **未處理**：尚未成為講師、也未暫不接受。

### 後台操作
- **查看會員**：每列可**另開新視窗**進入該會員詳情頁，於該處指派書籍講師身分（指派後該筆即轉為「已成為講師」）。
- **暫不接受**：對未處理者點「暫不接受」，可填**備註**後確認；系統記錄時間與操作管理者。
- **取消暫不接受**：對暫不接受者可還原回未處理。

### 儀錶板提示
- 後台首頁功能卡副標題會**動態顯示待辦**：
  - **推薦講師**卡：有未處理推薦時顯示「有 N 筆待處理推薦」。
  - **教材作業**卡：有待處理訂單時顯示「N 筆待批價/確認款項/出貨」。

## 十六、學習歷程回饋審核

學員可於「學習紀錄」頁自助回報學習歷程問題，管理者於後台審核並補資料。

### 清單與狀態
- 進入點：後台首頁「**學習歷程回饋**」功能卡（有待處理時副標題顯示「有 N 筆待處理回饋」）。
- 路徑：後台 **學習歷程回饋**（`/admin/learning-feedback`）。
- 以狀態分頁：**待處理／已處理／已婉拒／全部**（預設待處理優先）。
- 每列顯示：送出者（可另開視窗看會員）、類別、學員填的老師名稱、課程、備註、送出時間。

### 三種類別與處理
- **遺失學習歷程** → 點「**處理**」，**搜尋並選擇正確老師**（依姓名／編號），確認後系統為該學員**新增一個課程**（標題標記「**（補建）**」）並直接標記**結業（2025/09/01）**。
- **老師名稱錯誤** → 點「**處理**」，先**選擇要移除的錯誤班級**（該學員既有報名），再**選擇正確老師**，確認後系統於同一交易內移除錯誤報名並於正確老師下重建結業。
- **應結業卻未結業** → 點「**處理**」，**選擇要更正的既有報名**，確認後將該報名改為**已結業（2025/09/01）**（該班未結業會一併補結業）。

### 其他
- **婉拒**：對回饋點「婉拒」可填理由後確認；學員會在自己的回饋列表看到婉拒與理由。
- 老師名稱由學員自由輸入，**一律由管理者選定系統內現有老師**；找不到老師時請先於會員管理建立/指派其講師身分。
- 已處理或已婉拒的回饋不會再次執行建檔等動作（避免重複建課）。

## 十七、班級學員管理

進入路徑：**課程詳情頁**（`/course/{課程編號}`）的「**已核准學員**」區塊，標題列右側有「**新增學員**」「**移除學員**」按鈕（**管理者與該課講師**皆可操作）。用於修復名冊問題：班級遺漏學員、重複帳號搬課、同名拆帳、換班移除。

### 新增學員
點「**新增學員**」填寫**Email 或啟動編號**（單一欄位，僅限**既有會員**）：
- **查得既有會員** → 表單顯示確認列（該會員顯示名稱＋啟動編號），送出後直接加入班級，**不會變更其帳號資料**。請先核對確認列避免掛錯人。
- **查無會員** → 提示「查無此會員，請確認 Email 或啟動編號」，**送出按鈕停用**、**不會建立新帳號**。如需新增從未登入過的學員，請先至**會員管理 → 新增會員**建立帳號後再回此處加入班級。
- **已結業（補登歷史資料）**：勾選並指定結業日，該學員直接以已結業身分加入（列入證書製作、師生階層與擋修判定）。⚠️ 若班級尚未結業，送出後**班級會一併標記結業**（表單有提示）。
- 同一學員已在班級中會擋下（「該學員已在此班級」）。

### 移除學員
點「**移除學員**」進入移除模式（各學員卡出現紅色「移除」按鈕並加顯**啟動編號**輔助辨識），再點一次退出：
- **已結業報名**會出現紅色警示視窗，列明影響（證書待製作卡片可能消失、師生階層、擋修資格），確認後才執行。
- 報名**已有教材寄送紀錄**時系統會拒絕，請先至教材管理處理。
- 換班情境：於原課程移除、（必要時）於新課程新增；講師可自行操作。

### 常見修復情境
- **班級遺漏學員**：新增學員＋視情況勾已結業；若該學員**從未建過帳號**，請先至**會員管理 → 新增會員**建立後再加入班級。
- **學員重複註冊、課程在舊帳號**：於各課程將**新帳號**加入（勾已結業帶結業日）→ 移除**舊帳號**報名 → 於會員管理**暫停**舊帳號。
- **同名同姓共用一個帳號**：於會員管理為第二人**新增會員**（或由課程頁以其 Email 建帳號）→ 將錯誤課程的報名移除、加到正確帳號。⚠️ 勿以「姓名前加單位」區分——真實姓名是**證書印製依據**，辨識同名者請用啟動編號與單位欄位。

> 所有新增／移除都會寫入課程操作 LOG（見第十八章），可隨時追溯。

---

## 十八、課程操作 LOG

進入路徑：**課程詳情頁**（`/course/{課程編號}`）底部「**課程操作 LOG**」區塊，**管理者與該課講師**可見（一般學員看不到）。

- 記錄範圍：**該課程的學員新增／移除**（本階段）。
- 每筆包含：時間、操作者（管理者或講師）、動作（新增學員／移除學員）、對象學員（姓名＋Email）、摘要（如「補登結業 2025/09/01」「移除已結業報名」）。
- 最新在前，顯示**最近 30 筆**（區塊註記總筆數）。
- 紀錄以**快照**保存：即使對象會員或課程之後被刪除，紀錄內容仍完整可讀。
